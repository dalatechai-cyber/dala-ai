UNSIGNED DRAFT — loaded by nothing. A platform block making BREVITY a rule rather than a
preference. For the founder's approval; I cannot sign it (check-mn-review.mjs signs by file
hash, and this is platform Mongolian that every tenant would read).

WHERE IT GOES: prompt/platform/02_style.mn.txt — a NEW block, not an edit to
00_gate_preamble. Editing the preamble would invalidate the signature on the highest-stakes
text in the system (it orders every gate), forcing a re-read of the whole checklist just to
add a style rule. A new file is a small, self-contained signature that can be removed again
without touching gate precedence.

SCOPE: EVERY TENANT. `prompt_blocks.vertical` stays NULL, which 0018 defines as "applies to
all". Brevity is a fact about how a person reads a chat message, not about hairdressing —
there is no version of this that is right for Matrix and wrong for GS Auto Center. (If a
non-chat channel is ever added, email say, this is the block to revisit.)

WHY IT IS NEEDED, MEASURED (54 model drafts, read 2026-09-17):
  median 138 chars · p90 364 · max 768 · 39 per cent over 200 · 24 per cent over 300
  · 44 per cent contain line breaks · mean 3.6 sentences
The median is FINE. The problem is the TAIL, so a rule aimed at the average would make good
short answers curt and fix nothing. Reading the four longest drafts, the behaviour is not
verbosity — it is CATALOGUE-ANSWERING: asked about greasy hair, the model explains CICA,
then the course schedule, then эмчилгээний хими, then advises consulting a specialist, then
gives the phone. 768 characters answering a question nobody asked.

Two things fall out of the same reading:
  - The model emits markdown — «**CICA эмчилгээ**». Messenger does not render it, so the
    customer sees the asterisks. That is a defect independent of length.
  - Every one of the long drafts ends at 7741-7777.

AND THE ANCESTOR ALREADY HAS THIS RULE. Matrix-Chatbot's lib/salonBrain.js:91, inside its
«СУВГИЙН ЗААВАР (Facebook Messenger)» addendum:
    «Хариултаа товч, ойлгомжтой, Messenger-т тохирсон байдлаар бич.»
In production for weeks, alongside "plain text only, no HTML tags". So this is a MEASURED
REGRESSION against the bot being replaced — the same shape as the photograph case (D-076),
and the third time that pattern has appeared. The wording below is deliberately stricter
than the ancestor's, because «товч» alone did not stop the ancestor cataloguing either;
what is new is rule (1), answer only what was asked, and rule (5), ask instead of list.

NOT THE LEVER: RECEPTION_MAX_TOKENS = 700. Hitting it is TERMINAL in model/reception.ts —
the partial text is discarded and the customer gets the handoff line. Lowering it to force
brevity converts long answers into refusals, which is strictly worse than a long answer.

THE CARVE-OUT IS LOAD-BEARING. Both options open by exempting «БЭЛЭН ХАРИУЛТ». Without it,
"be brief" reads as licence to trim an approved sentence — and D-065 measured the model
dropping «би» from the handoff line unprompted, D-077 measured it adapting
refusal_price_unlisted. A brevity rule is precisely the instruction that would justify that
drift to a model trying to comply. gate/pinned.ts would catch and correct it, but the place
to prevent it is here.

--------------------------------------------------------------------------
OPTION A — full (628 chars, ~439 tokens, +4.5 per cent of every tenant's prefix)
--------------------------------------------------------------------------

=== ХАРИУЛТЫН ХЭВ МАЯГ ===
(Энэ хэсэг «БЭЛЭН ХАРИУЛТ»-ын мөрүүдэд ХАМААРАХГҮЙ. Бэлэн хариултыг үргэлж нэг ч
 үсэг өөрчлөхгүйгээр яг хэвээр нь бич — богиносгохыг ч бүү оролд.)

(1) Хэрэглэгчийн асуусан зүйлд ЗӨВХӨН хариул. Асуугаагүй үйлчилгээ, нэмэлт
    тайлбарыг өөрөөсөө бүү нэм.
(2) Хариулт 2–3 өгүүлбэрээс хэтрэхгүй.
(3) Жагсаалт, зураас (-), гарчиг, од (**) бүү ашигла. Messenger эдгээрийг
    хэвээр нь харуулдаг тул хэрэглэгч од, зураасыг нүдээрээ шууд хардаг.
(4) ЗӨВХӨН энгийн бичвэр. HTML тэг бүү ашигла.
(5) Хэрэглэгчийн хүсэлт тодорхойгүй бол сонголт бүрийг тайлбарлахын оронд
    НЭГ богино тодруулах асуулт асуу.

OPTION B — compact (431 chars, ~301 tokens, +3.1 per cent) — RECOMMENDED
--------------------------------------------------------------------------

=== ХАРИУЛТЫН ХЭВ МАЯГ ===
(«БЭЛЭН ХАРИУЛТ»-ын мөрүүдэд ХАМААРАХГҮЙ — тэдгээрийг нэг ч үсэг өөрчлөхгүйгээр
 яг хэвээр нь бич, богиносгохыг ч бүү оролд.)

(1) Асуусан зүйлд нь ЗӨВХӨН хариул. Асуугаагүйг бүү нэм.
(2) Хариулт 2–3 өгүүлбэрээс хэтрэхгүй.
(3) Жагсаалт, зураас (-), гарчиг, од (**), HTML тэг бүү ашигла — Messenger
    эдгээрийг хэвээр нь харуулдаг.
(4) Тодорхойгүй бол сонголт жагсаахын оронд НЭГ богино тодруулга асуу.

Same five rules, ~130 tokens cheaper on every cached prefix, for every tenant, for ever.
A block about brevity that is itself padded is the wrong artefact.

--------------------------------------------------------------------------
COST
--------------------------------------------------------------------------
- Ongoing: +3.1 (B) or +4.5 (A) per cent on the cached prefix. D-072 measured the prefix at
  86.7 per cent of the bill, so this is roughly +3-4 per cent on a cache-miss reply, for
  ever, for every tenant.
- One-off: a new revision invalidates the cache, so each tenant's next conversation pays one
  cold start — about $0.04 each at the 1h rate. Per tenant, not per conversation.
- Against that: the drafts this should remove are 400-768 characters of OUTPUT tokens, billed
  at the uncached output rate. A shorter answer is cheaper to generate than a long one, so
  the net is plausibly a saving. NOT measured — it depends on how the model responds to the
  rule, and the mirror is what would measure it.

WHAT PUBLISHING TAKES, IN ORDER
--------------------------------------------------------------------------
1. You sign: move the chosen text to prompt/platform/02_style.mn.txt and add its sha256 to
   prompt/platform-mn-review.json. check-mn-review.mjs fails the build until both match.
2. `node scripts/prompt/generate-seed.ts` -> a new migration writing the prompt_blocks row.
   The seed is GENERATED, never hand-copied, because a copy is what D-020 says will drift.
3. Push that migration; read the ledger before merging anything that reads it (D-058).
4. Republish EVERY tenant: deploy, `git pull`, publish — three steps, not two (D-074:
   scripts/publish/tenant.ts renders with YOUR checkout).
5. Every tenant's content_hash moves. Expect content_hash to change on all of them;
   allowed_numbers should NOT move — if it does, something else changed too.

One code change rides with it: src/lib/prompt/tenant.test.ts maps block headings to block
ids and needs «ХАРИУЛТЫН ХЭВ МАЯГ» added, and generate-seed.test.ts lists the block keys.
Both are test fixtures, not customer text.

FOUR QUESTIONS

2. «2-3 өгүүлбэр» — or a harder «2 өгүүлбэр»? The median draft is already about 2 sentences,
   so 3 codifies current good behaviour; 2 would shrink it further.
3. Rule (3) names the asterisk explicitly. Keep it? It is the one item a customer literally
   sees as noise — but naming a token also teaches it to a model that might not have used it.
4. Should this block also carry the «Та» honorific and tone, as the ancestor's addendum does
   («эелдэг, найрсаг боловч ажил хэрэгч»)? D-069 flagged the model mixing registers —
   «тавтай морил» beside «Танд» — and that is still unfixed. It would fit here, and it would
   make the block bigger. Your call, and a separate decision from brevity.
